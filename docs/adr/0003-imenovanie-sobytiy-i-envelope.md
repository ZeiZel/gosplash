# ADR 0003. Именование событий и обязательный Envelope

- **Статус:** принято, 2026-09-12
- **Фаза:** 0

## Контекст

Сейчас в проекте: сущность `Image`, топики `image.uploaded`,
`image.uploaded.retry`, `image.uploaded.dlq`, `image.processed`, `image.deleted`,
`license.purchased`. Сообщение — голый protobuf-payload
(`events.v1.ImageUploaded`) без обёртки; `event_id` лежит внутри payload'а;
заголовков Kafka нет вовсе.

Спецификация (§3.1) требует:

- имена топиков `<domain>.<entity>.<event>` в прошедшем времени:
  `media.photo.uploaded`, `media.photo.thumbnail-ready`,
  `catalog.listing.published`, `order.order.placed`, `wallet.account.debited`,
  `analytics.photo.viewed`;
- обязательный `Envelope` с `event_id` (uuid v7), `event_type`, `aggregate_id`,
  `occurred_at_unix_ms`, `schema_version` и `google.protobuf.Any payload`;
- заголовки Kafka: `event_id`, `event_type`, `traceparent`, `producer`.

Текущая схема `image.*` не различает домен и сущность. Это незаметно, пока
сущность одна, и ломается сразу, как появляются `wallet` и `order`: по имени
`image.processed` нельзя понять, кто продюсер, а список топиков перестаёт
читаться как карта системы.

Отсутствие Envelope дороже. Без него:

- каждый консьюмер обязан заранее знать тип сообщения в топике — а топик с
  несколькими типами событий одной сущности (`placed`, `paid`, `completed`)
  становится невозможен;
- дедупликация требует разобрать payload, то есть нельзя отсеять дубль, не
  умея его десериализовать;
- нечего положить в DLQ осмысленно: `event_type` и `event_id` битого сообщения
  недоступны ровно тогда, когда они нужнее всего;
- нет `schema_version`, то есть эволюция схемы не отслеживается.

Цена перехода: правятся `kafka-init` в compose, продюсер и консьюмер, модели
media и catalog, демо-цели `Makefile`, `.env.example`, `README.md`, `TODO.md`.
Час механической работы.

## Решение

Полный переход на конвенцию спецификации, в фазе 0 вместе с переездом
структуры ([ADR 0001](0001-struktura-repozitoriya.md)).

1. **Сущность `Image` → `Photo`** в media и catalog: тип, таблица (`images` →
   `photos`, `catalog_images` → `listings`), поля контрактов, HTTP-пути
   (`/media/images` → `/media/photos`).
2. **Топики** переименовываются согласно §3.1. Старые удаляются
   (`make topics-recreate`) — данных, которые жалко, в них нет.
3. **`Envelope`** вводится сразу, в фазе 0, а не откладывается до фазы 1
   вместе с `pkg/kafkax`. Причина практическая: без конверта метаданные
   (`event_id`, `occurred_at`) пришлось бы держать в самих payload-сообщениях
   и удалять оттуда позже — а удаление поля ломает контракт, и `buf breaking`
   справедливо это заблокирует. Дешевле определить payload'ы правильно
   с первого раза.
4. **Заголовки Kafka** — вместе с Envelope. `traceparent` пишется в заголовки,
   а не в payload: это W3C-стандарт, его понимает OTel-пропагатор без нашего
   кода, и трассировка продолжается через топик (см. `pkg/kafkax/trace.go`).

Правила эволюции остаются прежними и не меняются никогда: поля только
добавляются, номера не переиспользуются, удалённые уходят в `reserved`,
нарушение ловит `buf breaking` в CI.

## Последствия

**Хорошее.** Список топиков читается как карта системы: видно продюсера, видно
сущность, видно факт. Консьюмер может фильтровать по `event_type` из заголовка,
не десериализуя payload. Дедупликация по `event_id` работает даже для
сообщений, которые не удалось разобрать. `schema_version` даёт возможность
обработать старую версию события иначе, не ломая контракт.

**Плохое.** `Any` стоит лишних байт (хранит полное имя типа строкой) и лишнего
шага в коде: payload надо распаковать через `anypb.UnmarshalTo`. Компромисс
осознанный — и это одна из причин, по которой protobuf-пакетам нужен namespace
(`gosplash.media.v1`, см. ADR 0001): полное имя типа внутри `Any` обязано быть
глобально уникальным.

**Разовая цена.** `Image` → `Photo` — механическое переименование, но трогает
~15 файлов и всю документацию. Делается одним коммитом вместе с переездом,
чтобы не оставлять репозиторий в состоянии «половина `Image`, половина `Photo`».

**Что становится несовместимым.** `TODO.md` и `README.md` в части имён топиков
и ручек устаревают и правятся в том же коммите. Команды вида
`make topic-tail T=image.uploaded` из истории терминала перестанут работать —
это ожидаемо и лечится `make topics`.
