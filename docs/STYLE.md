# Соглашения кода

Проект учебный. Это меняет всё остальное: код здесь пишется для чтения, и
объяснение, почему сделано так, — часть работы, а не необязательное дополнение.

## Комментарии

Пишутся **на русском** и отвечают на вопрос «почему», а не «что».

```go
// Плохо: увеличиваем счётчик на единицу.
// Хорошо: счётчик отдельным полем, а не COUNT(*) по таблице:
// просмотров на порядки больше, чем карточек, и COUNT заставил бы
// PostgreSQL читать всю таблицу на каждый показ ленты.
```

Обязательный комментарий в трёх местах:

1. **Заголовок пакета** — зачем пакет существует и чего в нём сознательно нет.
2. **Применение паттерна** — с префиксом `// PATTERN: <имя> — ...` и разбором
   цены: что паттерн даёт и чем за это платят.
3. **Неочевидное решение** — почему `fnv`, а не `maphash`; почему ключ
   партиционирования `photo_id`, а не `author_id`; почему таймаут именно здесь.

Чего не нужно: пересказ сигнатуры, `// Get возвращает...`, TODO в местах,
где обещан работающий паттерн.

## Ошибки

- Оборачиваются с контекстом: `fmt.Errorf("upsert карточки: %w", err)`.
- Доменные ошибки — переменные в `internal/domain`, сравниваются через
  `errors.Is`. Адаптеры переводят их в свой язык: HTTP → статус, gRPC → `codes`.
- В gRPC наружу только `status.Error(codes.X, ...)`, никогда голый `err`.

## Логи

`log/slog`, всегда с контекстом там, где он есть: `slog.ErrorContext(ctx, ...)`.
Контекст обязателен, потому что `pkg/otelx` достаёт из него `trace_id` —
без него строка лога не связывается с трейсом.

Пары «ключ — значение», не форматирование: `slog.Info("kafka →", "topic", t)`,
а не `slog.Info(fmt.Sprintf("kafka → %s", t))`.

## Раскладка сервиса — ports & adapters

```
internal/domain/    предметная область. Без тегов gorm/json/protobuf,
                    без импортов инфраструктуры и gen/go.
internal/ports/     интерфейсы, объявленные рядом с ТЕМ, КТО ИМИ ПОЛЬЗУЕТСЯ.
internal/app/       сценарии. Импортирует только domain и ports.
internal/adapters/  pg, kafka, redis, grpc, http — по одному на технологию.
migrations/         не в internal: сюда ходит tools/automigrate.
cmd/<сервис>/       композиция зависимостей, только здесь.
```

Доменная модель и строка таблицы — **разные типы** с ручным отображением.
Две функции лишнего кода на сущность; взамен изменение схемы не правит
предметную область.

Появился в `internal/app` импорт `gorm`, `kgo`, `redis`, `grpc` или
`net/http` — сценарий прорастает в инфраструктуру, и его больше нельзя
протестировать без докера. Это ошибка, а не компромисс.

## Тесты

- Table-driven, `testify` (`require` для того, без чего тест дальше
  бессмысленен; `assert` для остального).
- Имена и сообщения об ошибках — на русском.
- Проверяются **свойства и поведение**, а не конкретные значения хэшей.
- Прикладной слой тестируется подделками портов, без контейнеров.
- Интеграционные тесты — `testcontainers-go`, с тегом сборки
  `//go:build integration`.

Отдельный приём: тест, который **должен упасть, когда придёт время**.
Если поведение временное и будет исправлено в следующей фазе, тест фиксирует
текущее состояние с комментарием, что его падение — сигнал обновить ADR,
а не поломка.

## Именование

- Топики: `<домен>.<сущность>.<факт-в-прошедшем-времени>`. Константы —
  только в `pkg/kafkax/topics.go`.
- Protobuf-пакеты: `gosplash.<домен>.v1`, путь файла обязан совпадать.
- Импорт сгенерированного кода — всегда с алиасом:
  `mediav1 "gosplash/gen/go/gosplash/media/v1"`.
- Go-пакеты инфраструктуры в `pkg/` — с суффиксом `x` там, где имя иначе
  столкнулось бы с библиотечным: `dbx`, `s3x`, `httpx`, `kafkax`, `redisx`.

## Конфигурация

`os.Getenv` вызывается **только** в `pkg/config`. Дальше по коду ходит
разобранная структура. Новая переменная — это правка `pkg/config/config.go`,
`.env.example` и `.env`.

Единственное исключение — утилиты в `tools/`. Это отдельные модули с
собственным `go.mod`, которые запускаются руками и не являются частью
рантайма сервисов; тащить в них весь `pkg/config` ради двух переменных
дороже, чем прочитать эти две переменные на месте. `tools/automigrate`
к тому же адресует базы ПО ИМЕНИ переменной (`target.envKey`) — для него
это не обход правила, а способ работы.

## Makefile

Цели новой фазы кладутся в отдельный файл `mk/<тема>.mk`, а не дописываются
в общий `Makefile`. Формат строки для `make help`:

```make
имя-цели: ## короткое описание
```

Раздел открывается строкой `## Название раздела` в отдельном комментарии.

## ADR

Каждое архитектурное решение — файл `docs/adr/NNNN-название.md` по схеме
**контекст → решение → последствия**. Последствия обязаны включать плохое:
ADR без раздела «чем платим» бесполезен. Номера зарезервированы в
[docs/adr/README.md](adr/README.md).

## Чего не делать

- Не менять GORM на другой слой доступа. `pgx` напрямую — только для
  outbox-relay и горячих путей, с замером и ADR
  ([0006](adr/0006-gorm-ostayotsya-pgx-tochechno.md)).
- Не публиковать в Kafka напрямую из хендлеров и сценариев: только через
  outbox ([0008](adr/)).
- Не использовать `KEYS` в Redis. Удаление — `UNLINK`, обход — `SCAN`.
- Не класть URL целиком в label метрики: `/media/photos/{id}` с миллионом id
  даст миллион временных рядов.
- Не оставлять `TODO: implement later` там, где обещан работающий паттерн.
